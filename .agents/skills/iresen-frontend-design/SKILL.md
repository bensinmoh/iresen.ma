# Frontend design

Read [PRODUCT.md](../../../PRODUCT.md), [DESIGN.md](../../../DESIGN.md) and the
target's current components/content before editing. Inspect available references;
do not assume named screenshots or approved copy are present.

State a short design read: visitor task, composition problem and useful direction.
Choose fidelity for an explicit reference match, refinement for a scoped improvement,
or redesign when the request calls for a replacement visual direction. Preserve
product truth, brand and approved routes in all three. Do not make selection or
approval rituals for routine reversible choices.

Build with shared tokens/components. Establish a clear first viewport, reading
order, typography, spacing and CTA hierarchy. Use only available approved content;
omit unsupported modules rather than filling them with invented claims. Expressive
public composition can use [Taste](../design-taste-frontend/SKILL.md), subject to
[IRESEN overrides](../README.md). Admin forms prioritize task clarity.

Apply responsive/accessibility work throughout. Finish visual implementation with
[visual QA](../iresen-visual-qa/SKILL.md). Report the problem, improvement, evidence
and remaining inputs. Record adopted shared rules in DESIGN.md and the specification.
